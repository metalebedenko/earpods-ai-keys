# Временная проверка центра на втором Mac

Файл: [EarPods-Dictation-Test.command](../tools/EarPods-Dictation-Test.command).

Это самостоятельная проба HID D8 на Mac15,13. Она не устанавливает приложение, не меняет файлы основного пакета, предпочтения диктовки/Siri или автозапуск. Поддержка D8 системой macOS ещё не подтверждена.

Результат от 2026-10-09: D8 не вызвал действий; исходное правило восстановлено. Затем автор выяснил причину поведения CF: при включённой Siri центр запускал её, а после выключения Siri заработала диктовка. Этот файл сохраняется как материал завершённой пробы и больше не является следующим шагом настройки.

1. Передать файл на второй Mac с уже активной схемой VoiceCommand / Backspace / Enter.
2. Подключить EarPods и запустить файл двойным кликом. Можно также выполнить `/bin/sh ./EarPods-Dictation-Test.command` из папки с файлом.
3. Нажать Enter для начала, затем проверить короткие нажатия центра в пустом документе TextEdit.
4. Вернуться в Терминал и выбрать результат 1–4. Скрипт вернёт точное правило установленного пакета и проверит readback.
5. Передать результат в чат. Основной пакет остаётся пригоден для дальнейшего теста uninstall.

Если прежняя проба осталась активна, повторный запуск сначала возвращает её и завершает работу. Для явного возврата есть `/bin/sh ./EarPods-Dictation-Test.command --restore`.

Выход и обработанные сигналы запускают попытку возврата только для точного D8-правила. Принудительное завершение SIGKILL не обрабатывается. При отключённых наушниках или изменившемся правиле возврат не гарантирован: скрипт сообщает об этом и сохраняет чужое правило. Если после подключения правило осталось пустым, потребуется `apply` основного пакета.

Проверка скрипта: 10 изолированных поведенческих тестов, включая обычное завершение, TERM/HUP, повторный запуск, чужие правила, неподходящий Mac, отказ инструмента и отключение устройства. Это программная проверка сценария; физический D8-тест ожидает результата пользователя.
